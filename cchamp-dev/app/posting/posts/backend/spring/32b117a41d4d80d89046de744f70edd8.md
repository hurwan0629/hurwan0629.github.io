### 먼저 Zustand 개념 이해


일단 지금부터 다시 이것저것 복습하기 전에 처음 사용해볼 Zustand 개념 정리를 하려한다.


Zustand는 React 전역 상태 관리 라이브러리로 Context보다 간단하고 Redux보다 가벼운 상태 관리 도구입니다.


React는 `부모 -> 자식 -> 자식 ...` 형태로 프로젝트가 만들어지게 되면서 상태를 공유하기 위해서는 `props drilling` 가 필요합니다. 하지만 이는 프로젝트의 복잡성을 주게 됩니다.


이전에 사용하였던 **Context**의 경우에는 `Provider` 을 통해 감싸야 할 필요가 있으며 `Provider` 이 바뀌게 된다면 전체를 리렌더링 한다는 문제가 존재합니다. 이때문에 나온 아이디어가 **Zustand**입니다. 

> Zustand의 핵심 아이디어는 **컴포넌트 밖에 상태를 두는 것** 입니다.

기본적으로 `npm install zustand` 를 해줄 필요가 있으며 


`import { create } from 'zustand'` 의 `create` 함수를 통해 상태 저장 공간을 만들 수 있습니다.


| 기술  | Context            | Zustand                           | Redux                              |
| --- | ------------------ | --------------------------------- | ---------------------------------- |
| 사용처 | 테마, 로그인 상태, 간단한 값  | 앱 상태가 많아질 때, 여러 컴포넌트가 공유할 때 (대규모) | 대규모 프로젝트, 디버깅 필요할 때, 매우 복잡한 프로젝트에서 |
| 장점  | React 기본 내장, 단순함   | 높은 자유도와 쉬운 상태관리                   | 데이터 흐름 강제를 통한 명확한 규칙, 강력한 디버깅 툴    |
| 단점  | 성능저하, 구조 꼬일 가능성 있음 | Context와 Redux의 중간                | 초기 설정을 할 것이 많음, 어려움                |
| 난이도 | 하 (소규모)            | 중 (중소기업)                          | 상 (대규모, 엔터프라이즈)                    |

```javascript
import { create } from 'zustand'

export const useCart = create((set) => ({
    count: 0,

    increase: () => {
        set((state) => ({count: state.count+1}))
    },

    decrease: () => {
        set((state) => ({count: state.count-1}))
    }
}))
```

이때 `create` 는 `store` 를 만들어주는 함수이며 `set`는 이전 상태를 받아서 새로운 상태를 반환해주는 코드입니다. `useStore` 는 React hook처럼 필요한 것만 선택하여 가져오는 함수입니다.


이후 이것을 이용하여 `count` 를 증가 및 불러오는 코드를 작성해주면 됩니다.

import { useState } from 'react'

}

import { useCart } from "../store/useCartStore"

export default function ItemlistPage() {

        </div>
    )
}
